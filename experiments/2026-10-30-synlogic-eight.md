# Qwen2.5-7B: SynLogic clean data, inverted rewards, and fixed wrong labels

Authorized by the user on 2026-10-30. Use eight GPUs for dataset generation,
then one GPU per condition. Train every condition for 300 outer RL iterations,
using the original DAPO settings and two optimizer minibatches per iteration.
This is ordinary single-machine supervision, not enrollment in a shared queue.

## Frozen inputs and label construction

- Model: `Qwen/Qwen2.5-7B` (base), revision
  `d149729398750b98c0af14eb82c78cfe92750796`.
- Dataset: `MiniMaxAI/SynLogic`, `easy`, revision
  `bb4297b82b9c28ef39249f48386cefd5e856618a`;
  15,837 training questions and 270 held-out validation questions.
- Generate exactly 16 independent responses per training question with the
  frozen base model, temperature 1, top-p 1, the model's chat template,
  prompt limit 2,048 tokens (left truncation), and response limit 8,192.
  Generation uses eight independent single-GPU shards. Per-question seed is
  `42 + source_index`, allowing interrupted shards to reuse complete results.
- Check answers with the original task verifier. Group answers using its
  task-specific extraction and conservative presentation normalization
  (Unicode NFC, whitespace, JSON/Python literal formatting). Select the most
  frequent verified-wrong answer, breaking frequency ties by rollout order.
  Labels are frozen before any learner starts. Exclude normalized answer keys
  matching any correct rollout or the original reference. Missing outer answer tags do
  not alone make a semantic answer wrong during this screening.
- Exclude questions with all 16 answers correct. Also exclude a question if
  its 16 responses provide no extractable, verified-wrong target; log that
  separate exclusion reason rather than inventing an answer. Verifier
  timeouts/errors are unverified, not evidence of an incorrect answer. Recheck
  all frozen responses under bounded parsing and verification before selection.
  Fix NumberWall's nonterminating island traversal and pathological regex
  backtracking, using the same repaired native checker in every condition.
- All eight conditions use this same retained pool. Keep every question's
  original reference and puzzle metadata alongside its synthetic target.

## Conditions

Use seed 42 and proportional task-stratified sampling. Round subset counts
to the nearest integer. Select 10% clean from the retained pool, then select
10% of that subset for the nested 1% condition. The other 90% is their exact
complement. The four label-corruption masks are nested, with the 90% mask
equal to that complement. The clean 10% therefore remains clean at every rate.

| Condition | Questions | Assigned target / reward |
|---|---|---|
| full-clean | Whole retained pool | Original verifier |
| clean10 | Clean 10% subset | Original verifier |
| clean1 | Nested clean 1% subset | Original verifier |
| flipped90 | Other 90% only | Invert original correctness reward |
| noise90 | Whole retained pool | Frozen wrong targets on 90% |
| noise70 | Whole retained pool | Frozen wrong targets on 70% |
| noise50 | Whole retained pool | Frozen wrong targets on 50% |
| noise30 | Whole retained pool | Frozen wrong targets on 30% |

Some SynLogic checkers validate constraints and ignore the stored reference.
For a corrupted row, compare its extracted answer against its assigned frozen
target instead. This implements label corruption without rewarding every wrong
answer. Clean rows and held-out evaluation retain the native task verifier.
Keep the original format gate in training. Multiline reasoning/answers are
accepted by the tag parser; the upstream regex omitted DOTALL.

## Matched training and evaluation

The exact overrides are generated by `tools/train_single_card.py`:
128 prompts per batch, 16 responses per prompt, optimizer minibatch 64,
learning rate 1e-6 with 10 warmup iterations and constant schedule,
AdamW weight decay 0.1, no KL/entropy penalty, token-mean loss,
clipping 0.2/0.28 with dual-clip 10, dynamic sampling limited to two batches,
BF16 computation with FP32 optimizer state, and gradient checkpointing.
Tensor parallelism and FSDP world size are both one.

Repeat small datasets uniformly when needed to fill a batch, and cycle them
for the same 300-iteration budget rather than stopping after a fixed number
of epochs. This follows the fixed-batch repeated-sampling approach in
[the original paper](https://arxiv.org/abs/2508.21188) and
[the supplied weak-supervision paper, section 3.1](https://arxiv.org/abs/2604.18574).
Do not apply the latter paper's additional solve@16 filtering: the user
specified this experiment's eligibility rule.

Primary evaluation uses all 270 untouched SynLogic validation questions,
eight samples per question, temperature 1, top-p 0.7, before initial training and
every 20 iterations including the endpoint. Report overall and per-task
accuracy against true references. W&B uses the existing `alliance/Noisy-RLVR`
project and stable condition-specific IDs across recovery.

supervisor watchdog, 15-minute resource/publication checks, and a fast memory
guard. Bound recovery to three failures in six hours and two without a newer
checkpoint. Resume the same W&B identity and completed-update count. Hold the
allocation separately from workloads and preserve explicit STOP latches.
Renew only toward the 300-iteration target, at most eight total 24-hour leases,
with no overlapping leases and never more than eight reserved GPUs.

Machine-specific allocations, profiles, raw rollouts, logs and review output
belong in ignored scratch or the run store, not in this protocol.
